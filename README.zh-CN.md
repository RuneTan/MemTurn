# MemTurn

[English](README.md) | [简体中文](README.zh-CN.md)

**有限记忆下持续学习 Agent 的经验整理与选择性内化框架。**

MemTurn 面向持续变化的任务流：在明确预算内保存经历，把相关经历整理成可复用记忆和训练材料，并协调参数版本发布与外部记忆退出。

仓库保留核心实现、组件约定和回归测试，不附带模型、API 客户端、模型下载脚本、小实验数据或试跑结果。使用者自行提供任务策略、经验组件、领域校验器和学习器。它不是开箱即跑的标准任务服务，也尚未证明持续学习优势。

## 系统怎样工作

1. 为当前任务固定模型版本和记忆视图，先检索再行动。
2. 根据本任务真实观察、动作和反馈写入有依据的经验。
3. 在有限区域内跨任务整理，产生替换记忆和对应训练材料。
4. 最多选择一条合格记忆，优先考虑不同任务的有效支持数。
5. 学习时屏蔽目标记忆及已识别的同源路径。
6. 准备新模型版本，然后原子更新发布指针并退出所选记忆版本。

按较慢固定轮次单独执行废退：处理冷记忆区域，在输入 token 数的一半预算内保留完整输出，不触发训练。发布成功只是工程流程完成，不代表已经验证模型掌握该经验。

## 维护周期

`Config.batch_size` 控制用进周期，默认每 4 个已计账来源任务终局检查一次。`Config.capacity_interval_batches` 为大于 1 的整数，开发默认 4；废退每 `batch_size * capacity_interval_batches` 个终局执行一次，默认 16。成功、失败和拒绝都按现有完成计数推进，只读探测不计入。废退使用同一 Consolidator，不内化。同轮到期先用进、再废退。

每次废退最多处理 `max_capacity_regions` 个冷区域，默认 2；占用率低也会执行。空区域或失败消耗本轮尝试，下一周期再处理。后台繁忙时合并错过的周期，不积累无界补跑；持久化尝试标记避免重启后重复领取，崩溃中断的已领取尝试不保证重做。硬容量上限仍会拒绝超限写入，不额外触发整理。旧参数 `capacity_trigger_ratio`、`capacity_target_ratio` 删除，旧配置需改用 `capacity_interval_batches`。以上数值是开发起点，正式实验前校准并冻结。
