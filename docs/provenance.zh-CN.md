# 来源与训练材料

[English](provenance.md) | [简体中文](provenance.zh-CN.md)

每条记忆都带有来源引用，因此可以追溯到“哪个任务、哪一步”。这些引用用于回看经历、构造训练材料，以及计算选择摘要时使用的来源覆盖数。

## 一条引用从哪里来

应用给每次任务经历分配唯一的 `task_id`，步骤从 0 开始编号。Writer 根据当前任务写出记忆，同时在 `supports` 中列出来源步骤，例如：

```json
[{"task_id": "task_a", "step": 2}, {"task_id": "task_a", "step": 5}]
```

Consolidator 整理多条记忆时，声明哪些输入记忆贡献了新摘要，并从这些父记录关联的任务中选择来源引用。摘要可以重新组织语言；引用把它连接回原始经历。

内置 `Validator(store)` 直接查库核对：任务是否仍可访问、步骤编号是否有效、父记录和来源是否属于本次允许的范围。摘要正文和适用条件也须填写完整。这是一套轻量的结构检查；摘要本身的质量通过抽查内容和后续任务表现来评价。

## 来源覆盖数怎么算

`source_coverage_count(memory)` 按有效引用中的任务 ID 去重计数。例如，摘要引用 `task_a` 的第 2、5 步和 `task_b` 的第 1 步，来源覆盖数就是 **2**。同一个任务出现多次只算一次。

默认用进按这个数选择学习目标，废退也按这个数确定优先保留哪些摘要。实现中引用字段叫 `supports`，最低来源数参数叫 `min_support_tasks`，默认值为 2。检索热度另用于标记近期使用和排列冷记忆。

## 两类训练材料怎样构造

| 材料 | 输入 | 训练目标 |
| --- | --- | --- |
| 规则问答 | 围绕摘要内容提出的问题 | 摘要全文或明确指定的正文片段 |
| 决策示范 | 来源步骤中的原始观察，以及该步之前的任务历史 | 该步骤实际执行、被环境接受或标记为可执行的动作 |

解码器根据引用复制决策示范的观察和动作；检查器再核对材料绑定的记忆版本、来源范围和原始内容。默认混合训练要求一条去重后的规则问答和至少一条决策示范。

材料按样本逐条处理：保留合格样本，合并完全相同的样本和重复正文引用，再按生成顺序应用数量上限。材料尚不齐备的摘要继续作为外部记忆供检索。问答中出现答案文字时会记录 `qa_text_overlap`，便于抽查；这种文字重合本身不会淘汰样本。

## 训练时模型读到什么

学习器接收训练材料、原始任务历史，以及筛选后的外部记忆。为了练习独立运用所选经验，外部记忆输入会排除目标摘要、父记录、同源记忆和相同正文的副本。历史由原始观察和动作重建，原样保留任务经历；过去检索出的记忆文本留在外部记忆通道处理。

完整输入接口见[组件与接口](components.zh-CN.md)。
