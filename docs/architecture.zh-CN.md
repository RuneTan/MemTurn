# 架构概况

[English](architecture.md) | [简体中文](architecture.zh-CN.md)

前台在固定的模型与记忆版本上执行任务；后台负责写入、整理和学习。后续发布新版本时，已经开始的任务继续使用自己的视图。

```mermaid
flowchart LR
  T[任务与观察] --> R[有界检索]
  R --> A[策略与环境交互]
  A --> W[有来源的经验写入]
  W --> B[外部记忆库]
  B --> C[区域巩固]
  C --> B
  C --> S[选择合格记忆]
  S --> L[使用者提供的学习器]
  L --> P[准备并发布版本]
  P --> B
```

## 两条维护路径

常规批次默认每完成四个来源任务触发一次。Consolidator 读取有限区域及仍可用的来源，产出替换集合。先完成来源校验与原子替换，再考虑学习。每批最多选择一条有至少两个不同任务支持的合格记忆。默认混合监督包括规则问答与真实来源决策；学习器必须遵守指定材料、屏蔽规则和训练预算。

候选模型准备成功后，系统在同一事务中更新发布指针并退出所选记忆版本。学习失败会保留已提交的外部巩固结果。退出不以掌握测试为条件。

容量紧张时单独处理冷记忆，按有效支持数排序，在处理输入 token 的一半预算内保留完整输出，返回条数由预算决定。这类事件不训练。

## 证据与权限

任务策略读取检索结果，不直接写库。Writer 读取一次公开经历；Consolidator 读取指定区域和可访问来源；校验器独立检查来源与领域有效性。生成的文字不能自行证明正确。隐藏答案和评估元数据不属于公开经历。

训练时屏蔽目标、父记录及已识别同源项。只读评估不刷新记忆热度，也不恢复待处理学习作业。审计日志供分析，不作为可检索经验库。

## 预算与恢复

`Config`、`Store`、`Runtime` 对活跃记忆、保留来源、队列、检索、监督材料和版本状态设置上限。SQLite 事务保护替换和发布；恢复记录保存待写经历、任务流位置与有界完成窗口。有限队列和任务期限支持到达负载计账。

使用者仍需在实际部署中约束总内存、显存、存储，并保证后端可取消。已有到达调度不是固定总时长评估器；全程截止、父链结算、检查点分支和科学评估需另行集成。不承诺无限去重或真实外部动作恰好执行一次。
