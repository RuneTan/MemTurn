## 修复内容

- 检索工具调用不再挤占环境动作步数；耗尽检索额度时返回空结果并提供有限的纠错机会。
- 同批次内的真实检索也会改变访问序号，容量提交可以拒绝过期冷排名；过长的最冷条目不会阻塞后续可处理条目。
- 常规作业按开始时的批次登记，Writer 异常也会推进维护；新区域巩固失败时，既有合格候选仍可被选择。
- 任务结果与待写来源原子登记；外部替换与提交记录原子提交；模型指针、选中记忆退出和发布记录原子提交。当前发布记录独立保留，不随历史作业轮换丢失；READY 不会在恢复时被当成已发布版本。
- Writer 只能引用本次任务；校验器异常拒绝认证；混合候选要求恰好一条规则问答。输出正文与作业样本预算在协调器统一检查。
- 学生检索排除具有独立来源的相同正文；输入与旧动作历史直接复述排除内容时，拒绝训练并保留记忆，不改造原生状态。语义改写的间接泄漏仍需领域检查。
- 旧任务仍引用退役模型时跳过下一次训练；适配器卸载不再持有前台数据库锁。重复关闭可安全返回，关闭流程等待已接收任务完成入队。
- 评估专用 Runtime 不执行恢复、Writer 或维护；评估快照退出不回收学习来源。
- 队列载荷计入来源预算；巩固前预留工作空间；HTTP 输入与输出均有字节上限；大 Writer 请求按实际请求规模预留额度。
- LoRA 延续和加载检查基座版本、rank、alpha、目标层与文件校验值；新增更新后数值检查、梯度统计、目标 token 统计及可复现初始化。
- 重启后未登记的模型目录也计入版本数量；达到上限时拒绝新训练，保留现有检查点供检查，不自动删除。

## 纠正问答诊断

`check_mixed_sft.py` 原先对规则问答调用 `training_messages(qa.prompt)`，默认得到的是要求输出动作 JSON 的提示。旧结果中的“问答探针输出动作对象”不能作为问答学习失败的证据。

现已显式传入 `qa.output_kind`。新的两轮检查每轮仍为 1 条问答、2 条原生来源动作、3 次更新，覆盖率 100%；正确文本提示下返回普通文本。回答较泛，并达到 96 个生成 token 的上限；没有验证规则掌握，没有退出外部记忆。原始历史产物未改动。

记录：`runs/audit_mixed_sft_20261024/report.json`。

## 仍未验收的边界

原生任务的自然语言领域判定、真实经验组件质量、匹配预算的长程对照、服务到达负载与尾延迟、可强制取消的后台作业、全部 GPU／RAM／磁盘峰值的联合硬预算仍未通过完整验收。SQLite 页数上限只约束主库，WAL／SHM 现在单独报告；不能将它称为总磁盘上限。远程服务 tokenizer 与运行模型的实际版本证明仍需冻结。

当前任务去重依赖有界的近期结果窗口；已经离开该窗口的任意旧 ID 重送，不具备永久 exactly-once 保证。正式恢复协议需要任务流位置／高水位和对应重放窗口。现有研究日志不能在正常执行中作为无限去重或来源数据库使用。
